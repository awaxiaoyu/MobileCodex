# MobileCodex 手机端 UI 设计稿

> 版本：0.3
> 状态：已按稿实现，待真机尺寸复核
> 设计方向：OpenAI / Apple 风格的简洁、高级、克制

## 1. 设计目标

MobileCodex 是手机上的 Agent 工作入口。首屏只承担一件事：让用户开始或继续一次 Agent 对话。聊天记录、项目上下文和设置放在主界面下层，通过右滑或菜单按钮露出，避免首屏被导航和管理信息占满。

设计关键词：

- 大面积纯白背景，黑色文字，状态色只用于连接和运行状态。
- 接近 SF Pro 的系统字体，标题清晰，正文保持舒适阅读尺寸。
- 控件减少装饰，依靠留白、细分隔线和轻阴影建立层级。
- 主界面、任务页、侧边菜单使用同一套间距和按钮规格。
- 所有长项目名和聊天名允许截断，但不能撑破布局。

## 2. 信息架构

```text
MobileCodex
├── Agent Chat（默认主页）
├── Task Chat（任务进行中）
└── Underlay Drawer（右滑显示）
    ├── Chats
    │   └── Recent
    └── 底部操作区
        ├── New chat
        └── Settings 入口
```

主页不显示独立的 Ask / Build / Review 导航栏。用户可以在输入框中直接描述任务，Agent 决定后续执行方式。

## 3. 页面设计

### 3.1 Agent Chat 主页

#### 顶部栏

从左到右：

1. 圆形菜单按钮，显示三条横线，点击打开下层菜单。
2. 标题 `Mobile Codex`。
3. 右侧连接状态：绿色圆点 + `Connected`。

菜单按钮在主页和任务页完全一致：白色圆形、无明显灰色填充、只保留柔和边缘阴影。

#### 内容区

- 中央欢迎内容：Sparkles 图标、`What are we building today?`、连接工作区提示。
- 可显示三条轻量快捷建议：`Review a diff`、`Plan a feature`、`Fix a bug`。
- 建议项使用底部分隔线，不使用卡片堆叠。
- 内容区可垂直滚动，但输入框始终固定在底部可见。

#### 输入区

- 占满内容区宽度，左右保留 13px 外边距。
- 圆角约 17px，白色表面，使用轻微阴影与边界区分背景。
- 第一行显示占位文字 `Message Codex…`。
- 第二行显示模式 `Default`、模型 `GPT-5.6` 和右侧发送按钮。
- 发送按钮为黑色圆形按钮，使用向上箭头图标。

### 3.2 Task Chat 任务页

#### 顶部栏

- 左侧仍为圆形菜单按钮，不使用返回箭头，也不切换成关闭图标。
- 标题显示实际项目和聊天名称：`MobileCodex/Mobile Codex redesign`。
- 标题单行显示，过长时使用省略号。
- 标题下方显示运行状态，例如 `Running · 18s`。

#### 时间线

- 使用左侧竖线连接用户消息、Agent 回复和工具进度节点。
- 用户消息使用浅灰气泡靠右显示。
- Agent 回复使用普通正文排版，不套大卡片。
- 工具状态使用小型白色状态行，例如 `Inspecting event stream`、`Checking generation guard`。
- 当前进度使用绿色小圆点或绿色状态文字，颜色只表示状态，不作为装饰。

#### 任务输入区

- 占位文字为 `Add direction to this task…`。
- 模式显示 `Plan`，模型显示 `GPT-5.6`。
- 发送按钮与主页相同，固定在底部。

### 3.3 Underlay Drawer 下层菜单

这是主界面右滑后显示的菜单，不是独立跳转页面。

#### 展开状态

- 菜单宽度约为屏幕的 80%，保证 `Chats`、最近聊天和底部操作区完整可见。
- 主界面向右移动，菜单从左侧露出。
- 主界面本身不加整体投影；阴影只落在与菜单相连的边缘，并使用较淡的柔和效果。
- 主界面前景层连接菜单的左上、左下角均以约 20px 小圆弧收口，阴影沿圆弧过渡。
- 连接处的空隙保持纯白，与菜单背景一致，不出现灰色缝隙。
- 菜单本身使用纯白背景；内容不使用大面积阴影或渐变。

#### Chats 区域

- 标题：`Chats`。
- 分组标题：`Recent`。
- 每条聊天显示消息图标、聊天名、辅助信息和相对时间。
- 有项目时显示完整名称：`项目名/聊天名`。
- 没有项目时只显示聊天名，不显示空的项目占位符或斜杠。
- 聊天条目之间保留极浅分隔线；Recent 与底部操作区之间不显示分隔线。

示例：

```text
MobileCodex/Mobile Codex redesign    Plan · 2 min ago       2m
Refresh task snapshot                 Default · Yesterday   1d
MobileCodex/Mobile app shell          Plan · Mon             3d
```

#### 底部操作区与 Settings

- 左侧显示带编辑图标的 `Chat` 新建聊天按钮。
- 右下角显示圆形齿轮设置按钮，点击后进入 Settings。
- Settings 页面包含 `Connected computer` 和 `Preferences` 入口，使用图标 + 文本 + chevron 的横向结构。

## 4. 交互规则

### 打开和关闭菜单

- 点击主页或任务页左上角菜单按钮，菜单进入展开状态。
- 从屏幕左侧向右拖动主界面，按拖动距离实时露出菜单。
- 拖动超过展开阈值后松手，菜单吸附到完整展开位置。
- 向左拖动主界面或点击遮罩区域，菜单回到关闭状态。
- 菜单按钮始终显示三条横线，不使用叉号替代。
- 展开和关闭使用短距离平滑位移动画，主页前景层和连接阴影同步移动。

### 聊天选择

- 点击最近聊天后关闭菜单，并恢复对应任务或聊天内容。
- 新建聊天后回到空的 Agent Chat 主页。
- 点击底部齿轮进入 Settings；设置页继续沿用同一套顶部栏和间距。

## 5. 尺寸和间距规范

以 390px 宽手机屏幕为设计基准，所有尺寸应使用响应式约束适配 320px 至 430px 宽度。

| 项目 | 规范 |
|---|---:|
| 页面左右内容边距 | 16–17px |
| 顶部栏最小高度 | 62px |
| 菜单按钮 | 36 × 36px，圆形 |
| 菜单按钮图标 | 18 × 18px，线宽约 2.2px |
| 顶部标题 | 22px，单行 |
| 任务标题 | 15px，单行省略 |
| 普通正文 | 14px 左右 |
| 辅助文字 | 9–12px，不低于 9px 的非关键时间标签 |
| 输入框圆角 | 17px |
| 输入框左右外边距 | 13px |
| 模式标签圆角 | 8px |
| 聊天行最小高度 | 44px |
| 菜单宽度 | 屏幕宽度约 80% |
| 菜单连接圆角 | 20px |
| 菜单连接阴影 | 仅连接边缘可见，低强度弧线阴影 |
| 底部安全区 | 保留系统 Home Indicator 空间 |

### 字体层级

```text
页面标题       22px / 650
欢迎标题       24px / 620
任务标题       15px / 650
聊天正文       14px / 400
菜单聊天名     12px / 550
辅助说明       12px / 400
分组标签       9–10px / 650，大写字母间距
```

字体权重控制在 Regular、Medium 和 Semibold 范围，避免整页使用粗体。

## 6. 颜色和层级

| 用途 | 颜色方向 |
|---|---|
| 主背景 | 纯白 |
| 主文字 | 近黑色 |
| 次要文字 | 中性灰 |
| 菜单按钮 | 白色 + 柔和边缘阴影 |
| 输入框 | 白色 + 轻阴影 |
| 发送按钮 | 黑色，白色图标 |
| 用户消息气泡 | 很浅的中性灰 |
| 聊天条目分隔线 | 极浅灰 |
| Recent 与底部操作区之间 | 透明，不显示分隔线 |
| 已连接 / 运行状态 | 低饱和绿色 |

不使用渐变、彩色背景、装饰性光晕或大面积彩色卡片。

## 7. Flutter 实现边界

当前设计稿只定义 UI 和交互，不改变 Bridge 协议或任务数据结构。实现时应保留以下产品行为：

- 主页默认进入 Agent Chat。
- 项目名和聊天名来自真实数据；无项目时隐藏项目名区域。
- 主页和任务页共用同一菜单按钮组件。
- 菜单为下层 Drawer 视觉，不替换成普通全屏导航页。
- 菜单展开时主界面仍保留在右侧；连接阴影只出现在主页与菜单的交界处。
- 输入框、流式回答、任务状态和聊天列表继续使用现有数据流。
